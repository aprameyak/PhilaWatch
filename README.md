# PhilaWatch

PhilaWatch is a React Native (Expo) app for people walking around Philadelphia. It shows a heatmap of recent crime incidents, lets users report signs of crime such as vandalism or broken lights, and ranks contributors on a public leaderboard.

Built at PennApps XXVI by [AmarDhillon05](https://github.com/AmarDhillon05) and [aprameyak](https://github.com/aprameyak).

## Features

- Crime heatmap over Google Maps, rendered with a deck.gl `HeatmapLayer` inside a WebView (`frontend/src/screens/MapScreen.tsx`), with filters for intensity, radius, and layer visibility.
- Search and incident detail screens backed by the crime incidents stored in MongoDB.
- User reports with location: the app reverse-geocodes the current position with the Google Geocoding API and posts the report to the backend.
- Photo check: the Snapshot screen sends a camera photo to a Roboflow object detection model (default project `graffiti-5sa0t`) and pre-fills a vandalism report when it finds a detection at 30% confidence or higher.
- Accounts, contribution counts, and a leaderboard of users by number of reports.
- A danger score from 1 to 5 for a location and time, generated by an LLM on Cerebras from nearby incidents in the 2025 crime CSV (`dbapi/`, see How it works).

## Tech stack

- Frontend: React Native 0.81, Expo 54, TypeScript, React Navigation, react-native-webview, deck.gl, Google Maps JavaScript API
- Backend: FastAPI, Motor/PyMongo, MongoDB, bcrypt
- Hackathon services: Flask + pandas + Cerebras SDK (`dbapi/`), FastAPI + SQLAlchemy + JWT (`authapi/`)

## Getting started

Prerequisites: Node.js, Python 3, a running MongoDB instance, and the Expo Go app or an iOS/Android simulator.

1. Create `.env` files from each `env.example`:

   ```bash
   ./setup-env.sh
   ```

2. Fill in the keys:
   - `frontend/.env`: `EXPO_PUBLIC_API_BASE_URL`, `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`, `EXPO_PUBLIC_ROBOFLOW_API_KEY`, `EXPO_PUBLIC_ROBOFLOW_PROJECT`, `EXPO_PUBLIC_ROBOFLOW_VERSION`
   - `backend/.env`: `MONGODB_URL`, `DATABASE_NAME`, `COLLECTION_NAME`, `USER_REPORTS_COLLECTION`, `USER_DATA_COLLECTION`, `USERS_COLLECTION`, `API_HOST`, `API_PORT`, `API_DEBUG`
   - `dbapi/.env`: `CSV_FILE_PATH`, `CEREBRAS`, `HOST`, `PORT`, `DEBUG`
   - `authapi/.env`: `DATABASE_URL`, `SECRET_KEY`, `ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, `HOST`, `PORT`, `DEBUG`, `CORS_ORIGINS`

3. Start the backend. `run.sh` creates a virtualenv, installs `requirements.txt`, and serves the API on port 8000 (docs at `http://localhost:8000/docs`). `stop.sh` frees the port.

   ```bash
   cd backend
   ./run.sh
   python seed_data.py   # optional: insert sample incidents into an empty collection
   ```

4. Start the app:

   ```bash
   cd frontend
   npm install
   npx expo start
   ```

The original hackathon services are optional. To run them, install each folder's `requirements.txt` and start `python api.py` in `dbapi/` or `python app.py` in `authapi/`. Note that `dbapi/score.py` also imports `mistralai`, which is not listed in `dbapi/requirements.txt`.

There are no automated tests.

## How it works

The app (`frontend/`) talks only to the FastAPI service in `backend/` through `frontend/src/services/api.ts`. `backend/main.py` exposes `/crime`, `/reports`, `/userdata` (including `/userdata/leaderboard`), and `/auth` routes, stored in MongoDB collections configured in `backend/database.py`. Roboflow and the Google Geocoding API are called directly from the app.

`dbapi/` and `authapi/` are the services written during the hackathon. `dbapi/api.py` is a Flask app that loads `dbapi/crime_2025.csv` (about 109,000 Philadelphia incidents from 2025) with pandas and serves `/crime`, `/incidents`, and `/score`. For `/score`, it finds events near the given latitude and longitude and `dbapi/score.py` asks `llama-4-scout-17b-16e-instruct` on Cerebras for a JSON danger score and list of reasons. Request and response shapes are in `dbapi/docs/routes.md`. The current app does not call `dbapi/` or `authapi/`.

```

backend/    FastAPI + MongoDB API used by the app
dbapi/      Flask crime CSV and danger score service (hackathon)
authapi/    FastAPI + SQLite auth service (hackathon)

```

## Background

Adapted from the original hackathon write-up by AmarDhillon05.

Before the hackathon, friends in Philadelphia told the team the city could be hard to walk in, and the first night there confirmed it. The goal was a social sustainability project that helps people avoid bad situations while making it lighter to talk about and report crime, which is why reporting is gamified with points and a leaderboard. The hardest parts were merging components that had been built against assumed APIs, and keeping the tone light enough to encourage contributions while staying serious about what witnessing a crime means. Ideas for next steps include time-and-place specific danger scores, larger object detection models beyond the current set of crime indicators, and getting the app in front of Philadelphia residents and police.
